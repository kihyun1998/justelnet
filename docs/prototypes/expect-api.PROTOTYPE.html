PROTOTYPE: 버리는 코드입니다. 기다렸다 보내는(expect) API의 모양을 정하려고 만들었습니다.

justelnet-expect: 장비 로그인을 손으로 돌려 보기

가상의 Cisco 라우터(R1)와 접속을 흉내 냅니다. 장비가 보내는 글자, 우리가 기다리는 것(expect), 우리가 보내는 것을 버튼으로 하나씩 진행하면서 상태가 어떻게 바뀌는지 볼 수 있습니다. 시나리오마다 Rust로 쓰면 어떤 코드가 되는지도 함께 보여 줍니다.

telnet 제어 바이트는 Core가 이미 걸러 냈다고 가정합니다. 여기 들어오는 것은 Data Event의 글자뿐입니다.

눌러 보면서 판단할 질문

  • A. 매칭 결과로 "몇 번째 패턴이 맞았는지"와 "그 앞에 온 글자(before)"를 돌려주는 방식이 쓰기 편한가요?
  • B. 매칭 뒤에 남은 글자는 버퍼에 남겨서 다음 expect가 쓰게 합니다. 이게 자연스러운가요? (시나리오 3)
  • C. 타임아웃을 오류(Err)로 줄지, 결과의 한 종류(Timeout)로 줄지. 타임아웃 때 그때까지 받은 글자를 보여 줘야 하나요? (시나리오 5)
  • D. 패턴은 문자열만으로 충분한가요, 정규식도 필요한가요? (시나리오 6)
  • E. --More-- 페이지 넘김을 라이브러리가 알아서 처리할까요, 사용자가 반복문으로 처리할까요? (시나리오 4)
